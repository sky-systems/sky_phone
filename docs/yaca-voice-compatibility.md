# Yaca voice compatibility

Checked on 2026-10-07 against all 53 official source tags, `v1.0.0` through `v3.6.0`, in [yaca-systems/fivem-yaca-typescript](https://github.com/yaca-systems/fivem-yaca-typescript/tags). This covers released resource APIs, not a certification of every TeamSpeak plugin, server configuration or modified fork.

## Incoming call failure

Phone's answer handler checks `Bridge.Calls.IsAvailable()` before adding both participants to the provider call. It previously accepted only the Lua boolean `true` from Yaca's `isEnabled()` export. Yaca forwards `GetConvarBool("yaca_enabled", true)` directly; a local FXServer 35265 reproduction returned numeric `1` in both JavaScript and Lua, making `1 == true` false. The same reproduction against the deployed old Phone bridge reported unavailable. This explains the displayed `voice_unavailable` rejection without a provider exception.

Yaca introduced the client/server status exports in [commit 32733ac](https://github.com/yaca-systems/fivem-yaca-typescript/commit/32733ac1ef34dbb7014ddaa5567f5504501e6554), first tagged in 3.0.7. The [3.6.0 server entry point](https://github.com/yaca-systems/fivem-yaca-typescript/blob/6d766a041671e0e76b3b63a31d068f21c8ded956/apps/yaca-server/src/index.ts) still forwards the native unchanged. Phone now accepts `true`/`1`, rejects `false`/`0`, diagnoses invalid returns and preserves the older missing-export path. A failing present export never becomes a legacy success.

## API history and adapter behavior

| Yaca resource versions  | Verified contract                                                                                                                                   | Phone behavior                                                                                                                                     |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.0.0–3.6.0             | Server `callPlayer(source, target, state)`, `muteOnPhone(source, state)`, `enablePhoneSpeaker(source, state)` keep their public parameters.         | Calls, payphones, speaker and mute use the same server-owned adapter.                                                                              |
| 1.0.0–3.0.6             | No client/server `isEnabled`.                                                                                                                       | Started Yaca uses the legacy path with one warning per Phone runtime.                                                                              |
| 3.0.7–3.6.0             | `isEnabled` forwards the native; `isPlayerTalking` is available.                                                                                    | Normalize status; use the current speaking getter.                                                                                                 |
| 1.0.0–1.10.0            | No `isRadioEnabled` getter.                                                                                                                         | Use the existing `enableRadio(true)` export.                                                                                                       |
| 1.x–2.x                 | Active-channel selection is `changeActiveRadioChannel`; raw secondary frequency reception exists.                                                   | Select the primary with the older export and preserve raw secondary reception. Dedicated secondary transmission remains a provider 3.x capability. |
| 3.0.0 onward            | `setActiveRadioChannel` and secondary-selection exports exist.                                                                                      | Use the modern selectors and preserve their toggle semantics.                                                                                      |
| Before 3.0.4            | `muteRadioChannelRaw` toggles and ignores an explicit state.                                                                                        | Frequency membership handles join/unmute and frequency `"0"` handles leave; do not invoke the old toggle on reconnect.                             |
| 3.3.0 only              | Public volume arguments are `(volume, channel)`.                                                                                                    | Match the installed resource manifest version and reverse arguments for that release.                                                              |
| Every other audited tag | Public volume arguments are `(channel, volume)`.                                                                                                    | Keep the normal argument order.                                                                                                                    |
| 1.x                     | Speaking is available through the external event and `yaca:lipsync`; early mute uses a zero `voiceRangeUpdate`, then `muteStateChanged` from 1.7.0. | Use the provider's events/state when newer getters are absent.                                                                                     |
| 2.0.0 onward            | Microphone mute/disabled getters and events are available.                                                                                          | Read current microphone state; errors keep capture muted.                                                                                          |

The oldest [phone export registrations](https://github.com/yaca-systems/fivem-yaca-typescript/blob/8272a70b3f4598ceee7bbe20648fcede532a7e18/yaca-voice/server/yaca/phone.ts) and [client speaking/mute path](https://github.com/yaca-systems/fivem-yaca-typescript/blob/8272a70b3f4598ceee7bbe20648fcede532a7e18/yaca-voice/client/yaca/main.ts#L745) establish the legacy contracts. The [1.11.0 radio registrations](https://github.com/yaca-systems/fivem-yaca-typescript/blob/86ed37f0e1829fbfdb58ce4d16fe2b34e17ec990/yaca-voice/client/yaca/radio.ts#L63) show the older selector/getter family. The [3.3.0 volume export](https://github.com/yaca-systems/fivem-yaca-typescript/blob/e80a92e6378c4fc37d11e0eb9a1007005adcfcdc/apps/yaca-client/src/yaca/radio.ts#L173) was reverted in [3.3.1](https://github.com/yaca-systems/fivem-yaca-typescript/commit/fc6edfbe82a3b1f0ec9cb1ba3e8ed775abbb53ae). Its official release ZIP also declares `version '3.3.0'`; do not infer the shipped version from the source checkout's package metadata.

## Cfx contract evidence

Inspected Cfx revision: `a74c2ccf0a56546dbb591b4545c643f56acebd3d`. This is the inspected upstream revision; an exact source SHA for the local FXServer artifact was not exposed.

- [GET_CONVAR_BOOL declaration](https://github.com/citizenfx/fivem/blob/a74c2ccf0a56546dbb591b4545c643f56acebd3d/ext/native-decls/GetConvarBool.md) and [ConsoleScriptFunctions.cpp](https://github.com/citizenfx/fivem/blob/a74c2ccf0a56546dbb591b4545c643f56acebd3d/code/components/citizen-scripting-core/src/ConsoleScriptFunctions.cpp): shared native, string name and boolean default; `GetConVar<bool>` converts the convar and passes its result to the script runtime. Numeric enabled representation is the observed runtime result, not an assumption about all artifacts.
- [Lua scheduler](https://github.com/citizenfx/fivem/blob/a74c2ccf0a56546dbb591b4545c643f56acebd3d/data/shared/citizen/scripting/lua/scheduler.lua#L626): export lookup emits the exact missing-export error; the wrapper preserves return values and propagates handler failures. Phone treats only lookup absence as optional.
- [GET_RESOURCE_METADATA declaration](https://github.com/citizenfx/fivem/blob/a74c2ccf0a56546dbb591b4545c643f56acebd3d/ext/native-decls/GetResourceMetadata.md) and [MetadataScriptFunctions.cpp](https://github.com/citizenfx/fivem/blob/a74c2ccf0a56546dbb591b4545c643f56acebd3d/code/components/citizen-scripting-core/src/MetadataScriptFunctions.cpp): shared native with resource/key strings and integer index; manifest metadata returns a string or no value. Used only for the known 3.3.0 argument reversal.
- [State bag documentation](https://docs.fivem.net/docs/scripting-manual/networking/state-bags/) and [Lua state-bag wrapper](https://github.com/citizenfx/fivem/blob/a74c2ccf0a56546dbb591b4545c643f56acebd3d/data/shared/citizen/scripting/lua/scheduler.lua): client `LocalPlayer.state` reads the provider-maintained speaking flag. Phone does not change that flag.

These are Cfx runtime APIs and provider contracts; no GTA engine-native implementation is required for the fix.

## Validation and limits

`tests/server_voice.lua` exercises the real Phone adapter with enabled/disabled numeric and boolean values, invalid returns, failing exports, missing legacy exports, stopped resources, call start/stop, controls and provider aliases. `tests/client_radio_restrictions.lua` covers the old selector/getter families, current dual channels, reconnect/leave and both volume parameter orders. `tests/client_realtime.lua` covers current getters, legacy speaking/mute events, Phone restart state and provider failure.

The actual numeric native result and old availability rejection were reproduced on the local server. After building, copying and restarting Phone 1.1.5 with OAL enabled, the deployed new adapter accepted the real native `1`, started a mocked Yaca call and rejected numeric `0` and a failing present handler in a runtime sandbox. Its configured live voice provider is PMA; Yaca and a multiplayer TeamSpeak session are not installed there. Tests and source coverage do not prove live two-player calls, speaker audibility, radio transmission or browser microphone/device behavior on every Yaca version. Those remain acceptance tests on a Yaca test server.
